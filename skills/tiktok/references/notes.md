# Discovery notes & gotchas

Captured live from a logged-in www.tiktok.com session with `secret-sauce`
(`playwright-cli record` + page-context probing). Kept here so the next person
doesn't re-learn them the hard way.

## Signing is main-world only

- TikTok's `/api/*` endpoints require anti-bot params (`X-Bogus`, `X-Gnarly`,
  `X-Dynosaur`, `msToken`). These are generated by `webmssdk`, which hooks
  `window.fetch` / `XMLHttpRequest` **in the page's main world**.
- **Works:** `playwright-cli eval-file <file> --tab=<id>` (main world) → the
  hook signs the outbound fetch → `200` with real data. This is what the skill
  uses.
- **Fails:** `browser.evalAsync` runs in an *isolated* world without the hook →
  signature-required endpoints return `status_code 10201` / HTTP 400. (Some
  lenient endpoints like search still succeed there, which is misleading —
  always test the strict ones like `/api/post/item_list/`.)
- **Fails:** plain Node `fetch()` — unsigned, wrong origin, cookies stripped.

## `aid` must be 1988, not `appId`

The web API id is `1988` for every `/api/*` call. But the page app-context's
`appId` is context-dependent — on `/messages` it is `1233`. Reading
`ctx.appId` and sending `aid=1233` makes signing fail (10201). Hard-code `1988`.

## Empty `200` = soft throttle

Firing ~10+ API calls within a few seconds makes TikTok return HTTP `200` with an
**empty body** (anti-abuse). It affects the strict endpoints (`item/detail`,
`post/item_list`) first while search/notice still work. Not a bug and not a
session-expiry — just back off. The skill retries once after 3s; beyond that,
wait ~30s or reload the tab.

## CDP execution context dies on a recording tab

A `playwright-cli record` tab that navigates within the SPA can lose its CDP
execution context (`Session with given id not found (-32001)`) — `eval` then
fails on that tab while `snapshot`/`click` still work. Recovery: close the tab
and open a fresh one (`tab-close` + `open`). For discovery, prefer probing from
a normal (non-recording) tab.

## VFS vs bash `/tmp`

`playwright-cli eval-file` reads from the SLICC VFS (`/__opfs__/slicc-fs/...`),
which is **not** the same filesystem as the ad-hoc bash tool's `/tmp`. From
`.jsh`, write the eval file somewhere in the VFS you also read back (the skill
uses `/workspace/skills/tiktok/.tmp/`). `fs.unlinkSync` was observed to be a
no-op here, so the skill reuses fixed filenames (overwritten per call) instead of
accumulating unique ones.

## Stripping newlines breaks `//` comments

The API-fetch expression is written to a file and run verbatim, so it can keep
newlines/comments. But any expression passed to `browser.evalAsync` is flattened
with `.replace(/\n/g,' ')` — a `//` line comment inside such an expression would
then swallow the rest of the code (`Unexpected end of input`). Keep those
inline expressions comment-free.

## Messages are DOM-only

Live caption-style capture doesn't apply; DM content is on the Frontier
WebSocket. The skill reads the conversation list and open-conversation bubbles
straight from the rendered `/messages` DOM, and sends by typing into the
`contenteditable` composer + Enter (best with the tab foregrounded, since key
events need it).

## Where the user identity comes from

`document.getElementById('__UNIVERSAL_DATA_FOR_REHYDRATION__')` →
`JSON.parse(...).__DEFAULT_SCOPE__['webapp.app-context']` carries `user`
(`uid`, `uniqueId`, `secUid`, `nickName`, `region`, `isPrivateAccount`), `region`,
`language`, and `wid` (used as `device_id`). `httpOnly` session cookies aren't in
`document.cookie` — but same-origin `fetch(..., {credentials:'include'})` from the
page sends them automatically.
