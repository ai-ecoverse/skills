Start with FluffyJaws

FluffyPacks help you start with the right context instead of a blank chat. Each pack is designed for a specific job, product area, or workflow.

What changes when you use a pack

When you open a FluffyPack, FluffyJaws becomes more focused.

Depending on the pack, it can:

start with a clearer purpose
show quick-start prompts or guidance
use tools or connected sources chosen for that task
steer the conversation toward the workflow the pack was built for

The main chat experience stays familiar. What changes is the quality and direction of the help you get from the start.

How to choose a pack
Start with Suggested for your org when it appears. These are the top five packs most used by nearby peers in the last 90 days, derived from existing Workday hierarchy and FluffyJaws usage metadata. Each suggested card explains the usage signal behind the recommendation.
Use Recently used when you want to continue with a pack you already tried.
Use Featured by Adobe for built-in packs maintained centrally.
Use Discover FluffyPacks when you want to browse the broader pack catalog.
Pick the pack whose title and description match your goal.
Prefer the most specific pack when you already know the domain.
Stay in the main app when you are exploring broadly and do not want a guided workflow.
Switch packs if the conversation feels too general or too constrained.

If you cannot open a pack, it is not currently shared with you.

How to start well

The best first message is clear about both the task and the outcome.

Good starting prompts usually include:

what you want done
the audience or level of detail
any important constraints
the source material or file to use

For example:

"Summarize this release note for a support handoff."
"Review this case history and list the main risks."
"Compare these two approaches and recommend the safer one."
How to get better results from a pack
Use the pack's quick starts when you want a reliable first prompt.
Add your own context instead of assuming the pack already knows it.
Ask follow-up questions to narrow, compare, or reformat the answer.
If a pack supports files or connected knowledge, give it the exact material that matters.
If the response feels off, say what to change: shorter, more specific, more cautious, or more actionable.
When to use a different pack

Change packs when:

your goal has changed
you need a different source of truth
you need a different tone or workflow
the current pack is too broad or too specialized for the task
Building your own pack

Most users only need to choose and use packs. Teams can use the builder to create packs for a product area, support workflow, release process, customer segment, or reusable analysis pattern. The builder supports custom instructions, a first-screen experience, indexed knowledge sources, exact SharePoint files, native FluffyJaws tools, selected Marketplace agents, Slack reply channels, access rules, config admins, and pack-scoped Insights.

If you want to create one for your team or workflow, use the builder guide in the advanced section.
